# Веб-интерфейс Portal

Прототип встроен в `portal-runtime` и доступен по корневому адресу его локального
HTTP API: по умолчанию http://127.0.0.1:51821/. Он работает с настоящими данными
runtime; демонстрационных устройств и отдельного сервера нет.

После изменения HTML, CSS или JavaScript пересоберите и перезапустите runtime:

```sh
cargo build -p portal-runtime
PORTAL_CONFIG=./portal-state/portal.json target/debug/portal-runtime
```

Откройте страницу, вставьте токен из файла `api_token_file` или выберите файл
кнопкой на странице входа. Runtime печатает путь к файлу при запуске. После
перезагрузки страницы токен нужно ввести снова.

## Структура

- `index.html` — страницы устройств, файлов и системы, диалоги, SVG-иконки.
- `styles.css` — оформление и мобильная раскладка.
- `app.js` — авторизация, опрос состояния каждые 5 секунд, команды и файлы.
- `favicon.svg` — значок приложения.
- `../runtime/src/web.rs` — встраивание ресурсов в бинарник.
- `../runtime/src/api.rs` — статические маршруты и HTTP API.

`POST /api/v1/state` принимает `{}` и возвращает ключ устройства, UDP listener,
флаг здоровья и доступности reload, список пиров и статистику активных сеансов.
`relay_server` в состоянии описывает собственное UDP-реле, если оно включено.
Объект `relay` в форме устройства содержит публичный ключ и UDP-адрес реле.
`POST /api/v1/peers/info` с `{"peer":"PUBLIC_KEY_HEX"}` запрашивает роль у
устройства по QUIC и сохраняет её для значка «Реле» в списке. Сведения доступны
по кнопке информации; открытие файлов также обновляет роль.
Остальные действия используют `/api/v1/command` и `/api/v1/files/*`.
Отсутствие сеанса у пира не означает недоступность устройства: соединение
открывается при файловом запросе.

Токен хранится в памяти вкладки, передаётся только в заголовке Authorization и
не включается в URL. Статика не содержит токенов; API проверяет loopback, Host,
Origin и bearer. Внешние скрипты, шрифты и стили не используются. Динамические
имена выводятся через DOM textContent; CSP запрещает встроенные скрипты и iframe.

## Ограничения прототипа

Доверенные ключи пока хранятся только в памяти runtime. Названия устройств —
локальные псевдонимы в localStorage данного origin. Публикуемая папка и её права
задаются в конфигурации, поэтому для файлового доступа нужно зарегистрировать
ключи с обеих сторон и разрешить читателя в `allowed_downloaders`.

Если включён `relay_server`, в «Системе» отображаются его UDP-адрес и подключения.
В форме устройства доступен флажок «Разрешить использовать моё реле», который
меняет `allow_relay` через `peer_upsert`. Он не даёт прав на файлы. Разрешение
действует до перезапуска; постоянный список задаёт `relay_server.allowed_peers`.
Клиенты выбирают используемые relay через `relays` в конфигурации; обнаружение
роли само по себе не меняет этот выбор.

Файловый сервис поддерживает чтение. Поиск файлов фильтрует текущую страницу,
по 50 записей. При наличии File System Access API скачивание пишется на диск
потоком; остальные браузеры собирают файл в памяти и сохраняют через Blob.
Большие скачивания в таких браузерах ограничены доступной памятью вкладки.

Проверка HTTP-интеграции: `python3 runtime/scripts/check-quic.py` после сборки
`portal-runtime` и `portal-cli`. Она проверяет статику, авторизацию, JSON состояния
и операции между двумя настоящими экземплярами runtime.
